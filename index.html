Human attestation verifier

Check whether a person read and approved the text of a GitHub issue, pull request or comment, with a touch on a hardware key, before an agent posted it under their account.

An issue, a pull request, or one of their comments (the link ending in #issuecomment-…). Public repositories only; the page reads GitHub's API without signing in.

Paste the raw Markdown instead

The body exactly as the API returns it, for example from gh api repos/owner/repo/issues/12 --jq .body. The rendered page hides the block, so copying from GitHub's view will not work. Without a link, the repository, kind and title cannot be checked.

Whose key this is

Every verdict rests on one public key, written into this page: the OpenPGP key of Augustin Bengolea, bengous on GitHub. Of its subkeys, only one counts. It was generated on a YubiKey with a touch policy that cannot be turned off, so each signature it makes needs a finger on the key.

What a valid result means

      
    
        
  • The key holder touched the YubiKey after a review window showed them this exact text, with the repository, the kind and, for an issue or a pull request, the title.
    • 
        
  • The touch proves presence and a chance to read. It does not prove every word was read, or who drafted the text: an agent usually did.
    • 
        
  • An edit after posting breaks the signature. A block copied to another repository, posted as another kind, or kept under a changed title fails its check.
    • 
        
  • No block proves nothing either way. Text typed by hand on GitHub carries none.

Check without this page

      
Fetch the raw body, rebuild the signed bytes, and let gpg judge. In a throwaway keyring:


export GNUPGHOME="$(mktemp -d)"
curl -s https://github.com/bengous.gpg | gpg --import
gh api repos/OWNER/REPO/issues/N --jq .body > raw.md
python3 split.py raw.md      # writes payload and payload.asc, prints the header
gpg --status-fd 1 --verify payload.asc payload | grep VALIDSIG

      
The first fingerprint after VALIDSIG must be the attesting subkey above, and the printed header must match the repository, the kind and the title GitHub shows. split.py and the format are in the README next to this page.
